PRD(`서술 실험실 PRD — 미션 01 감자 세포 농도.md`)를 구현한 학생용 게임 + 교사 히트맵입니다.
학생 답안과 판정 결과는 **Google Apps Script 웹 앱**을 통해 Google 스프레드시트에 쌓입니다.

```
edu_sciw_v1/
├─ web/                     ← 정적 웹 앱 (아무 정적 호스팅에나 올리면 됨)
│  ├─ index.html            학생 게임 (탐색 → 주장 → 반박 → 변론 → 클리어)
│  ├─ teacher.html          교사 히트맵 (반 코드 입력)
│  ├─ missions/mission01.js 미션 설정 파일: 장면·단서·퀘스트·교수 대사·판정 사전
│  ├─ js/config.js          ★ Apps Script URL을 넣는 곳
│  ├─ js/game.js            게임 엔진 (뼈대/메커닉만)
│  ├─ js/judge.js           키워드 판정 엔진 (LLM 실패 시 대체)
│  ├─ js/api.js             백엔드 통신 (큐·재전송·로컬 모드)
│  ├─ js/art.js             장면 그림 (SVG)
│  └─ js/teacher.js, css/   교사 화면, 스타일
└─ apps-script/
   ├─ Code.gs               백엔드 (기록 저장, 히트맵 데이터, 선택적 LLM 판정)
   └─ appsscript.json       매니페스트
```

## 1. 바로 해 보기 (서버 없이)

`config.js`의 `API_URL`이 비어 있으면 **로컬 모드**로 동작합니다. 기록이 그 브라우저(localStorage)에만 저장되고,
같은 브라우저에서 `teacher.html`을 열면 히트맵도 볼 수 있습니다.

```bash
python -m http.server 8765 --directory web
```

→ 학생: http://localhost:8765/index.html · 교사: http://localhost:8765/teacher.html

## 2. Apps Script 백엔드 배포

1. 새 Google 스프레드시트를 만듭니다 (예: "서술 실험실 기록").
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. `Code.gs` 내용을 `apps-script/Code.gs`로 통째로 바꿉니다.
4. (권장) 왼쪽 **프로젝트 설정 → "appsscript.json" 매니페스트 파일 표시**를 켜고, `apps-script/appsscript.json` 내용으로 바꿉니다.
5. 편집기에서 함수 `setup`을 선택해 **실행** → 권한 승인. 시트에 `Sessions`, `Attempts` 탭이 생깁니다.
6. **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
7. 나온 웹 앱 URL(`https://script.google.com/macros/s/…/exec`)을 `web/js/config.js`의 `API_URL`에 붙여 넣습니다.

> Code.gs를 고친 뒤에는 **배포 관리 → 편집 → 새 버전**으로 다시 배포해야 반영됩니다(URL은 그대로).

## 3. 웹 앱 올리기

`web/` 폴더를 그대로 정적 호스팅에 올리면 됩니다 (GitHub Pages, Netlify Drop, 학교 웹 서버 등).
학생에게는 `index.html` 주소를, 교사는 `teacher.html?class=반코드` 주소를 쓰면 됩니다.

## 4. (선택) LLM 판정 켜기

Apps Script 편집기 **프로젝트 설정 → 스크립트 속성**에 추가합니다.

| 속성 | 값 |
| --- | --- |
| `ANTHROPIC_API_KEY` | Anthropic API 키 (서버에만 저장되고 학생 브라우저에는 가지 않음) |
| `LLM_MODEL` | (선택) 기본값 `claude-opus-5-5` |
| `LLM_FALLBACKS` | (선택) `off`로 두면 거절 시 자동 대체 모델 기능을 끔 |

편집기에서 `testJudge`를 실행해 연결을 확인할 수 있습니다.

- 판정 요청에는 학생 답안 텍스트와 체크 항목만 들어갑니다. 반 코드·출석번호는 보내지 않습니다.
- PRD대로 **3초 안에 답이 없으면 키워드 규칙으로 판정**하고, 그동안 교수의 "흠…" 연출이 지연을 덮습니다.
  Apps Script를 거치는 왕복 + 모델 응답이 3초를 넘는 경우가 많아, 실제로는 키워드 판정이 자주 쓰일 수 있습니다.
  더 기다리게 하려면 `config.js`의 `LLM_TIMEOUT_MS`를 늘리세요. 키가 없어도 게임은 끝까지 진행됩니다.

## 5. 저장되는 기록 (PRD 7.2)

**Sessions** (학생 1명 × 1판 = 1행): 세션 ID, 반 코드, 출석번호, 미션 ID, 시작·종료 시각, 단계별 소요 시간(ms),
수집한 단서·모형 카드, 클리어 유형(full/partial), 처음 답(칠판), 최종 답 원문, 최종 판정(`finalC`…`finalWB`),
퀘스트 통과 여부(`questPassed`), 처음 오류, 오류 횟수, 힌트 횟수·단계, 판정 방식(llm/keyword).

**Attempts** (입력 1회 = 1행): 세션 ID, 단계·퀘스트 ID, 시도 번호, 입력 원문, 판정 JSON, 진단·오류 유형,
힌트 단계(0~2), 소요 시간, 판정 방식.

학생 화면은 기록을 큐에 모아 묶어서 보내고, 네트워크가 끊기면 브라우저에 보관했다가 다시 보냅니다(중복 저장 방지).
최종 변론 제출은 즉시 전송되며, 교사 히트맵은 20초마다 자동 갱신됩니다.

## 6. 교사 히트맵 (PRD 7.3)

- 행: 출석번호 · 열: C, D, W1, W2a, W2b, W3/WB + 처음 오류(N1, N2, E1, E2, E3) + 힌트·클리어
- **진한 칸** 최종 변론에서 자기 말로 씀 · **줄무늬 칸** 최종 변론에서 카드 문장으로 채움 · **옅은 칸** 퀘스트에선 했지만 최종 변론에서 빠뜨림 · **빈칸** 끝까지 못 함
- 최종 변론은 "카드 골라 넣으며 쓰기"(기본)와 "내 말로만 쓰기" 중 학생이 고릅니다. 카드 문장을 뺀 나머지로 다시 판정해 자기 말로 쓴 요소를 따로 저장합니다(`finalJudgment.own`).
- 맨 위 한 줄 요약: "가장 많이 빠진 워런트: W2b (62%) · 가장 많은 처음 오류: N2 (40%)"
- 칸을 누르면 그 학생의 해당 입력 원문(처음 답, 퀘스트 시도, 최종 답)이 옆에 열립니다.
- 같은 학생이 여러 번 했다면 클리어한 가장 최근 판을 보여 줍니다.

## 7. 두 번째 주제 만들기 (스킨 교체)

1. `web/missions/mission01.js`를 복사해 `mission02.js`로 만들고 `window.SCIW_MISSIONS.m02 = {…}`로 내용을 바꿉니다
   (실험 데이터, 단서, 주장 선택지, 퀘스트·대사, 판정 사전 `lexicon`).
2. `index.html`·`teacher.html`의 `<script src="missions/mission01.js">`를 새 파일로 바꾸고, `config.js`의 `MISSION_ID`를 `m02`로 바꿉니다.

조작 유형 3가지(막 통과 끌어다 놓기 `membrane`, 슬라이더 평형 `slider`, 두 결론 결합 `combine`)는 엔진에 있으니 설정에서 고르면 됩니다.

## 알아 둘 점

- PRD대로 로그인이 없습니다. 반 코드를 아는 사람은 누구나 그 반 히트맵을 볼 수 있으니, 짐작하기 어려운 반 코드를 쓰세요.
- 키워드 판정은 교과서식 표현을 넓게 잡도록 만들었지만 연구 수준의 정확도는 아닙니다(PRD 비목표). 애매한 답은 LLM 판정이 더 낫습니다.
- 설탕물 농도는 퍼센트 농도 0·5·10·15%를 씁니다(PRD의 0·0.2·0.4·0.6 M 자리). 질량 변화는 농도와 헷갈리지 않게 g으로 씁니다(+8 g, +3 g, −5 g, −10 g). 정답 범위는 5~10%입니다. 값은 `mission01.js`의 `data`·`answer`·`massUnit`에서 바꿉니다.
- 학생이 질량 변화를 %로 써도, 키워드 판정은 '질량'·부호 뒤의 %나 '늘·줄' 앞의 %를 농도로 세지 않습니다.
- 대상 화면: 1024×768 이상 가로 화면(태블릿·크롬북·노트북). 휴대폰 세로는 PRD 비목표입니다.

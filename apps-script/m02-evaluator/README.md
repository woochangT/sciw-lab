# 미션 02 AI 평가 서버

기존 기록 저장용 Apps Script와 분리된 평가 전용 프로젝트다. 기존 `apps-script/Code.gs`에 덮어쓰지 않는다.

## 배포 파일

저장소 루트에서 `node tools/export-m02-apps-script.cjs`를 실행하면 `.local/m02-apps-script`에 다음 파일을 생성한다. 이 명령은 업로드나 배포를 실행하지 않는다.

- `Code.gs`: 평가 요청 처리와 호출량 상한
- `Rubric.gs`: 브라우저와 동일한 루브릭 v1.1
- `appsscript.json`: 서울 시간대, V8, 외부 API 호출 권한

평가 서버는 시트를 읽거나 쓰지 않으므로 스프레드시트 접근 권한을 요청하지 않는다.

## 서버 속성

Apps Script의 프로젝트 설정에서 다음 스크립트 속성을 설정한다.

| 속성 | 값 |
| --- | --- |
| `OPENAI-API-KEY` | 사용자가 직접 넣는 OpenAI API 키 |
| `M02_JUDGE_ENABLED` | `true`일 때 평가 요청 허용 |
| `M02_OPENAI_MODEL` | 기본값 `gpt-5.4-mini-2026-03-17` |
| `M02_DAILY_LIMIT` | 기본값 `300`회, 서울 날짜 기준 |
| `M02_MINUTE_LIMIT` | 기본값 `30`회 |

API 키를 소스 파일, GitHub 또는 브라우저 설정에 넣지 않는다. 사용량은 `M02_USAGE` 속성에 기록한다. 서버가 공급자 요청을 보내기 전에 호출 횟수를 예약하며 공급자 오류가 난 요청도 횟수에 포함한다. 상한에 도달하면 평가를 보류하고 답안을 보존하며 규칙 판정으로 전환하지 않는다.

## 연결과 확인

웹 앱을 배포한 뒤 실제 `/exec` 주소를 강철솜 `web/js/config.js`의 `JUDGE_API_URL`에 넣는다. 기록용 `API_URL`은 유지한다. GitHub Pages에서 로그인 없이 호출하려면 웹 앱을 배포자 권한으로 실행하고 모든 사용자에게 접근을 허용해야 한다. 이 주소를 알면 평가를 요청할 수 있으므로, 위의 상한은 사용자 인증을 대신하지 않는다.

평가 주소의 GET 응답은 서비스 이름, 루브릭 버전과 `ready`만 반환한다. 키나 학생 답안은 반환하지 않는다. `ready: true`는 키와 활성화 속성의 존재만 확인한 값이므로 실제 API 인증과 판정 성공은 별도의 예시 제출로 확인한다.

서버 배포와 GitHub 프런트엔드 배포는 별개다. 평가 서버 연결을 확인한 뒤 `front-end`의 설정을 올리고, `main` 반영은 별도로 진행한다.

## 현재 연결 상태

2026-11-02 루브릭 `m02-docx-1.1.0`으로 별도 평가 서버를 배포하고 강철솜 `web/js/config.js`에 연결했다. Google 계정 로그인 없이 배포 주소로 요청할 수 있고, 배포자 계정으로 실행한다. API 키 원문이나 학생 답안을 공개 상태 응답에 포함하지 않는다.

배포 버전 3에서 합성 답안 9건의 진행 판정과 두 최종 통과 경로를 확인했다. 실제 게임 API 클라이언트로 최종 글 강조 구절과 해요체 설명도 확인했다. 소수의 합성 예시 점검이며 실제 학생 답안 전체의 정확도 검증은 아니다. 기존 기록 백엔드와 팀 시트는 변경하지 않았다. GitHub Pages의 실제 화면 반영은 main 배포와 별개다.

# 교사용 화면 · 미션 02

2026-11-01 UI 초안. 저장소 루트 `index.html`은 실험실 소개와 미션 02 진입 페이지이며, `teacher.html`은 강철솜 미션 전용 대시보드다. 학생 게임 진입 화면도 같은 디자인으로 정리했다. 기존 미션 01 게임은 해당 폴더 주소로 계속 접근할 수 있다.

## 로컬 미리보기

저장소 루트에서 `python3 -m http.server 8765 --bind 127.0.0.1` 실행 후 `http://127.0.0.1:8765/`와 `http://127.0.0.1:8765/teacher.html`을 연다. 기본 데이터는 24개 고유 학생 번호와 27판의 합성 예시이며 실제 기록을 자동 조회하지 않는다.

## 화면과 집계

- 반 개요: 누적 고유 번호, 첫 판 최종 제출, 최근 판 완료·진행·종료 미상, 실제 관찰 사건의 단계 분포. 숫자 번호의 공백과 선행 0을 정규화하고 QA/TEST, m01, 중복 ID와 충돌 번호를 제외한다. 전체 재적 학생 수나 능력 순위는 추정하지 않는다.
- 학급 증거: 행동 기록/기회 제시/미관찰, 별도의 게임 자동 인정/미인정/미관찰 표시. 학생 선택 시 원문과 타임라인으로 이동한다.
- 학생 상세: 첫 판·최신 판·각 판 선택, 최초 생각/첫 최종 제출/마지막 제출, 힌트 해제와 열람, Q1~Q3와 제출 사건. 옛 데이터의 누락된 사건·시각·버전은 미기록으로 표시한다.
- 변화 보기: 동일 학생의 첫 판과 최신 판의 원문 비교. 버전이 다르거나 누락되면 판정 비교를 보류한다. 문장 차이 강조는 의미나 능력 평가가 아니다.
- 수업 계획: 교사 작성 질문·활동·다른 가능성/판단·후속 일시, 상태 전환과 수정. 이 브라우저의 별도 localStorage에 저장하고 학생 원문을 수정하지 않는다. **M02_Review 서버 저장과 교사 로그인은 이번 UI 작업 범위에 포함하지 않았다.**
- 기간·버전은 대표 판과 관찰 행렬을 좁히며, 누적 고유 번호 분모와 누적 첫 제출·최근 상태 카드는 유지한다.

입력 중인 반이 바뀌면 이전 반 자료를 즉시 비우고 늦은 응답을 버린다. 학생 상세를 열거나 교사 계획을 작성하는 동안 자동 갱신으로 내용을 교체하지 않는다. 키보드 포커스, 네이티브 dialog, 모바일 배치, reduced-motion을 지원한다.

# 기존 저장 API 배포 기록

같은 스프레드시트의 `감자`, `강철솜`에 미션당 한 탭을 사용한다. 열은 `recordType`, `recordId`, `sessionId`, `classCode`, `studentNo`, `missionId`, `createdAt`, `updatedAt`, `payload` 순서다. 세션과 시도를 별도 행으로 저장하고 키는 유형+ID다. 기존 `Sessions`, `Attempts`에도 같은 기록을 함께 저장한다. 두 쓰기 중 하나가 실패하면 실패 응답을 반환하며 클라이언트 재전송으로 복구한다. 배포 전에 시작된 세션은 기존 Sessions에서 읽어 미션 탭에 복원한다. 같은 학생이 여러 판을 한 기록과 시도 원문도 남긴다.

학생 기존 batch 프로토콜과 감자 클라이언트 URL은 유지한다. 2026-10-31 사용자 Google 권한 승인 후 기존 웹 앱 URL에 버전 2를 배포했다. 두 미션 각각 startSession/logAttempt/updateSession 묶음을 두 차례 전송하고, 미션별 탭과 Sessions/Attempts에서 최종 답과 시도 기록 및 중복 방지를 확인했다. 강철솜 학생 클라이언트도 같은 API에 연결했다. 새 교사 화면은 기본 합성 예시이며 서버 주소를 비워 기본 차단한다. 외부에서 쉽게 추측할 수 없는 교사 키를 서버 Script Properties에 등록하고, 검증된 배포 주소를 `teacher/config.js`에 지정해야 서버 조회를 시도한다. 비밀 키는 정적 파일이나 URL에 넣지 않는다. GET 원문 조회는 새 버전에서 차단된다.

## 필수 보안 한계

제공된 시트는 링크를 아는 누구나 편집 가능한 상태로 확인되었다. 이 상태에서는 교사 API에 키를 붙여도 시트 자체에서 기록을 직접 읽거나 바꿀 수 있어 학생 데이터 보호가 되지 않는다. 운영 전 파일 공유 권한을 담당자가 직접 제한하고, 로그인 기반 교사 인증, 학생 쓰기 인증과 남용 방지, 서버 판정·입력 검증, 정보 보존·삭제 정책을 마련해야 한다. 기존 학생 batch 쓰기는 호환성을 위해 인증되지 않으며 학생 전송 판정은 검증되지 않은 참고 자료다. 비밀번호 공유 방식은 계정 인증을 대체하지 않는다. 이 코드만으로 운영을 승인할 수 없다.

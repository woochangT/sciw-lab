# 현재 버전 · 선생님의 수업 기록장

2026-11-01 사용자 피드백 반영. 우창님 main(PR #4)의 실험실 배경, 칠판 간판, 두 미션의 실루엣 키링은 유지한다. 인트로에는 키링의 미세한 흔들림과 첫 등장만 더하고, 교사용 링크를 실제 기록장으로 연결했다. 교사 화면도 같은 실험실 배경·나무 테두리 칠판·핀으로 고정한 메모로 구성했다.

## 바로 실행

저장소 루트에서 `python3 scripts/local_server.py --port 8765`를 실행한다. 인트로는 `http://127.0.0.1:8765/index.html`, 교사용 화면은 `http://127.0.0.1:8765/teacher.html`이다. 단순 `http.server` 대신 이 서버를 사용해야 시트 조회가 동작한다.

기본값은 **연결된 Google 시트**다. 서버가 강철솜 탭의 session/attempt payload를 읽고, 반 목록과 선택한 반의 기록을 로컬 화면에 전달한다. 예시 자료로 자동 대체하지 않는다. 새 기록 불러오기는 원본을 다시 읽으며, 화면을 보고 있을 때 20초 간격으로 조회한다. 학생 답안을 열거나 수업 메모를 작성하는 동안 자동 갱신을 멈춘다.

## 선생님이 보는 순서

1. **우리 반 살펴보기:** 참여/최종 답안 있음/최종 답안 없음 메모를 눌러 학생을 추린다.
2. **학생 답안 읽기:** 출석번호 오른쪽의 답안 읽기를 누른다. 처음 생각과 마지막 답안을 먼저 보여주고, 제출별 원문·활동 이력·게임 자동 판정은 펼쳐 볼 수 있다.
3. **수업 메모 남기기:** 학생의 말에서 확인할 질문과 활동을 적는다. 수업 메모는 이 브라우저에 별도로 저장하며 학생 답안과 판정을 수정하지 않는다.

## 실제 시트 연결 범위

- 기존에 링크로 읽을 수 있는 대상 시트의 Google Visualization CSV 인터페이스를 이용한다. [Google 공식 연결 문서](https://developers.google.com/chart/interactive/docs/spreadsheets). 기존 공유 설정과 Apps Script 교사 인증을 변경하지 않는다.
- 대상은 동일한 스프레드시트의 `강철솜` 탭이다. 미션 01은 교사 집계에 포함하지 않는다. 원본 Sessions/Attempts를 중복 합산하지 않는다.
- 2026-11-01 검증 당시 수업용 반 기록은 없었고 `test` 반의 시험 플레이 1판, 활동 36개가 있었다. UI에서 **시트의 테스트 기록**으로 분명히 구분하며, 수업용 인원과 섞지 않는다. 자동 검증 QA 기록은 시험 보기에서도 제외한다. 실제 수업 반이 추가되면 목록에 나타난다.
- 로컬 API는 `127.0.0.1`에만 바인딩하고 반별로 응답을 나눈다. 다른 웹 Origin 요청은 거부하며 파일에 학생 원문이나 인증 정보를 저장하지 않는다. 메모를 작성해도 시트에는 쓰지 않는다.
- 이 연결은 현재 로컬 미리보기용이다. 정적 호스팅에 HTML만 올리면 `/api/sheet`가 없으므로 동일하게 작동하지 않는다. 시트가 비공개로 바뀌면 인증된 별도 읽기 연결이 필요하다. 조회 실패는 실패로 표시하며 0명 또는 예시 수업으로 바꾸지 않는다.

# 기존 저장 API 배포 기록

같은 스프레드시트의 `감자`, `강철솜`에 미션당 한 탭을 사용한다. 열은 `recordType`, `recordId`, `sessionId`, `classCode`, `studentNo`, `missionId`, `createdAt`, `updatedAt`, `payload` 순서다. 세션과 시도를 별도 행으로 저장하고 키는 유형+ID다. 기존 `Sessions`, `Attempts`에도 같은 기록을 함께 저장한다. 두 쓰기 중 하나가 실패하면 실패 응답을 반환하며 클라이언트 재전송으로 복구한다. 배포 전에 시작된 세션은 기존 Sessions에서 읽어 미션 탭에 복원한다. 같은 학생이 여러 판을 한 기록과 시도 원문도 남긴다.

학생 기존 batch 프로토콜과 감자 클라이언트 URL은 유지한다. 2026-10-31 사용자 Google 권한 승인 후 기존 웹 앱 URL에 버전 2를 배포했다. 두 미션 각각 startSession/logAttempt/updateSession 묶음을 두 차례 전송하고, 미션별 탭과 Sessions/Attempts에서 최종 답과 시도 기록 및 중복 방지를 확인했다. 강철솜 학생 클라이언트도 같은 API에 연결했다. 새 교사 화면은 기본 합성 예시이며 서버 주소를 비워 기본 차단한다. 외부에서 쉽게 추측할 수 없는 교사 키를 서버 Script Properties에 등록하고, 검증된 배포 주소를 `teacher/config.js`에 지정해야 서버 조회를 시도한다. 비밀 키는 정적 파일이나 URL에 넣지 않는다. GET 원문 조회는 새 버전에서 차단된다.

## 필수 보안 한계

제공된 시트는 링크를 아는 누구나 편집 가능한 상태로 확인되었다. 이 상태에서는 교사 API에 키를 붙여도 시트 자체에서 기록을 직접 읽거나 바꿀 수 있어 학생 데이터 보호가 되지 않는다. 운영 전 파일 공유 권한을 담당자가 직접 제한하고, 로그인 기반 교사 인증, 학생 쓰기 인증과 남용 방지, 서버 판정·입력 검증, 정보 보존·삭제 정책을 마련해야 한다. 기존 학생 batch 쓰기는 호환성을 위해 인증되지 않으며 학생 전송 판정은 검증되지 않은 참고 자료다. 비밀번호 공유 방식은 계정 인증을 대체하지 않는다. 이 코드만으로 운영을 승인할 수 없다.

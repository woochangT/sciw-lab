## 학급 오버뷰와 히트맵

- 첫 화면에서 시트에 있는 여러 반의 게임 참여·답안 작성 현황과 요소별 성취 히트맵을 함께 본다. 학년 필터와 게임 전환은 오버뷰의 범위를 좁히며, 반 선택을 가로막는 입력 단계가 아니다. 테스트는 명시적으로 켜서 따로 보고 자동 QA는 항상 제외한다.
- 반 이름/카드를 누르면 해당 반의 두 게임 요약으로 들어간다. 히트맵 칸은 해당 반·게임 분석으로 바로 연결한다. 상세 화면에서 전체 학급 오버뷰로 돌아올 수 있다.
- 같은 반의 번호는 최신 판으로 한 번씩 센다. **다른 반에 같은 출석번호가 있어도 서로 다른 참여 번호**이다. `3-2`, `03-02`, `3학년 2반`은 같은 반으로 모으되 원래 입력 코드를 보존한다. 2반을 10반보다 먼저 정렬하고 불명확한 코드의 학년을 추측하지 않는다.
- 색 칸의 비율은 **해당 요소가 인정된 번호 / 그 요소의 최종 판정이 있는 번호**이다. 미제출·미기록은 분모에서 빼며 `—`로 표시한다. 명시적인 미인정 0%와 구분한다. 퀘스트 통과나 초기 진단을 최종 성취로 대체하지 않는다. 마지막 최종 제출의 판정이 있으면 게임 종료 전에도 그 제출을 읽을 수 있다.
- AI 루브릭 1.1/1.2, 단어 규칙과 버전 미기록 기록은 판정 기준 선택으로 분리한다. 버전 미기록 결과는 참고 자료이며 같은 기준의 반 간 성취 차이를 확정하지 않는다. 색뿐 아니라 비율·인원과 설명을 함께 제공하며 반을 성취 순위로 정렬하지 않는다.
- 게임 상세의 학생 히트맵에서 칸을 누르면 원문과 자동 판정이 열린다. 학생 능력 점수나 교사의 최종 평가가 아니다. 원문을 읽고 수업 질문을 선택하는 데 사용한다.

## 요약과 리포트

선택한 게임 분석 맨 위에 ‘무엇을 함께 티칭할지’ 헤드라인과 수업 초점을 크게 표시한다. AI 도움을 별도 탭으로 두지 않는다. 자세히 보기는 저장된 결과로 바로 열리며 다음을 포함한다.

1. 생성 당시 반·게임·처음/최근 판 범위, 참여/최종 답안/명시 힌트 열람 집계와 막대그래프
2. 답안 근거가 있는 관찰과 다른 가능성·확인할 점
3. 게임별 실험 자료: 감자는 농도·질량 변화 그래프, 강철솜은 열린/닫힌 측정 범위 그림과 수치
4. 교사가 사용할 확인 질문과 짧은 활동
5. 생성 당시 처음/최종 답안 발췌(번호 제외, 각 400자, 최대 24판), 한계

인쇄/PDF 저장 버튼은 브라우저 인쇄를 연다. 인쇄 CSS에서 조작부·배경을 제외하고 리포트를 출력한다. 직접 적는 메모는 학생 답안 읽기 아래 또는 학생 상세에서 유지한다. 학생 원문/판정은 변경하지 않는다.

## LLM 호출·저장 규칙

- **생성 / 재생성 버튼에서만 호출**한다. 최초 진입, 반·게임 선택, 탭/리포트 열기, 새로고침, 20초마다 시트 조회, 저장 리포트 복원은 LLM을 호출하지 않는다.
- GPT-6 Luna `reasoning.effort: medium`, Responses API, `store: false`, JSON Schema 출력. 기존 Script Property `OPENAI-API-KEY`(또는 `OPENAI_API_KEY`)를 서버에서만 사용한다. 학생 판정 API의 기존 모델은 이 작업의 변경 범위가 아니다.
- 최초 생성은 동일 입력의 단기 서버 캐시를 재사용할 수 있다. **재생성은 `regenerate: true`로 캐시를 건너뛰어 다시 호출**한다. 프로젝트 전체 UTC 기준 6회/시간, 20회/일 제한은 유지한다. 실패하면 기존 리포트를 지우지 않는다.
- 브라우저 localStorage에 통합 리포트를 저장한다. 워크북/자료 출처/반/테스트/게임/처음·최근 판별로 분리한다. 읽는 시트가 바뀌면 변경 표시만 하고, 리포트 본문·자료는 생성 당시 상태를 유지한다. 개인정보를 포함할 수 있는 리포트를 Git이나 디자인 서비스로 보내지 않는다.
- 로컬 POST는 같은 Origin만 허용하며, 브라우저가 보낸 집계를 신뢰하지 않고 선택한 반·게임의 시트를 다시 읽는다. LLM 입력은 반 코드·번호·세션 ID를 제외한 집계와 답안 발췌다. 이메일/전화 패턴을 제거하지만 자유서술 전체의 자동 익명화를 보장하지는 않는다.
- AI API는 입력만 분석하며 저장 시트의 기록을 조회/반환하지 않는다. 기존 `classData` 인증은 유지한다. 테스트/소수 표본 일반화, 미제출을 오개념으로 판단, 학생 능력 점수·순위·자동 처방은 금지한다.

# 기존 저장 API 배포 기록

같은 스프레드시트의 `감자`, `강철솜`에 미션당 한 탭을 사용한다. 열은 `recordType`, `recordId`, `sessionId`, `classCode`, `studentNo`, `missionId`, `createdAt`, `updatedAt`, `payload` 순서다. 세션과 시도를 별도 행으로 저장하고 키는 유형+ID다. 기존 `Sessions`, `Attempts`에도 같은 기록을 함께 저장한다. 두 쓰기 중 하나가 실패하면 실패 응답을 반환하며 클라이언트 재전송으로 복구한다. 배포 전에 시작된 세션은 기존 Sessions에서 읽어 미션 탭에 복원한다. 같은 학생이 여러 판을 한 기록과 시도 원문도 남긴다.

학생 기존 batch 프로토콜과 감자 클라이언트 URL은 유지한다. 2026-10-31 사용자 Google 권한 승인 후 기존 웹 앱 URL에 버전 2를 배포했다. 두 미션 각각 startSession/logAttempt/updateSession 묶음을 두 차례 전송하고, 미션별 탭과 Sessions/Attempts에서 최종 답과 시도 기록 및 중복 방지를 확인했다. 강철솜 학생 클라이언트도 같은 API에 연결했다. 새 교사 화면은 기본 합성 예시이며 서버 주소를 비워 기본 차단한다. 외부에서 쉽게 추측할 수 없는 교사 키를 서버 Script Properties에 등록하고, 검증된 배포 주소를 `teacher/config.js`에 지정해야 서버 조회를 시도한다. 비밀 키는 정적 파일이나 URL에 넣지 않는다. GET 원문 조회는 새 버전에서 차단된다.

## 필수 보안 한계

제공된 시트는 링크를 아는 누구나 편집 가능한 상태로 확인되었다. 이 상태에서는 교사 API에 키를 붙여도 시트 자체에서 기록을 직접 읽거나 바꿀 수 있어 학생 데이터 보호가 되지 않는다. 운영 전 파일 공유 권한을 담당자가 직접 제한하고, 로그인 기반 교사 인증, 학생 쓰기 인증과 남용 방지, 서버 판정·입력 검증, 정보 보존·삭제 정책을 마련해야 한다. 기존 학생 batch 쓰기는 호환성을 위해 인증되지 않으며 학생 전송 판정은 검증되지 않은 참고 자료다. 비밀번호 공유 방식은 계정 인증을 대체하지 않는다. 이 코드만으로 운영을 승인할 수 없다.

### 2026-11-03 루브릭 근거·단계별 대화

학생별 히트맵의 항목을 누르면 그 제출에 저장된 루브릭 체크, 판정 이유, 답안과 일치하는 인용문 및 판정에 사용한 원문을 먼저 보여준다. 인용문 불일치·이전 근거 미기록은 별도 표시하며 재판정이나 AI 호출로 보충하지 않는다. 감자의 defense/FINAL 제출도 최종 근거로 읽는다.

두 게임은 화면에 실제 표시한 교수 대사를 professorSpeech 이벤트로 기록한다. 강철솜의 처음 생각이 통과하지 않은 경우도 답변·평가를 남긴다. 교사 상세 화면에서 단계별 학생 답변·LLM 피드백·표시 대사를 읽는다. 본문은 16px, 작은 설명·히트맵 글씨는 최소 14px로 키웠다.

시트 저장은 새 로그부터 미션 탭의 로그인당 세션 한 행을 갱신한다. I열 payload에는 세션, J:Q의 history1~8에는 원문 대화 배열을 나눠 저장하고, R:T에는 처음 생각·최종 답안·읽기용 대화를 둔다. JSON 원문 대화는 최대 360,000 UTF-16 코드 단위이며, 초과는 잘라 버리지 않고 저장 실패로 반환해 클라이언트 큐에 남긴다. 셀 경계에서 이모지를 분리하지 않는다. 단계·attemptId·순서를 보존하고 재전송은 중복을 만들지 않는다. 새 Attempts 행은 추가하지 않으며 Sessions의 요약 한 행은 호환용으로 유지한다. 기존 개별 attempt 행은 삭제하지 않고 함께 읽는다. 미션 탭의 기존 9개 열을 유지하며 뒤에 대화 열을 추가한다. 서버·로컬 리더 모두 A:T를 읽어 기존 행과 새 행을 지원한다.

GitHub Pages는 호스팅 API를 사용하며 이 배포의 자산 버전은 journal-v2다. 읽기 요청의 일시적 네트워크·502/503/504 오류는 한 번 재시도하고, 실패를 빈 반으로 바꾸지 않는다. 재시도는 GET 시트 조회에만 적용하며 AI 생성 요청은 자동 재시도하지 않는다.

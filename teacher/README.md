# 교사용 예시 화면과 기존 Apps Script

각 미션 시작 화면에서 **교사용 대시보드 예시 보기**를 선택하거나 `teacher.html`을 연다. 기본 화면은 합성 데이터이며 실제 학생 기록이 아니다. 예시의 미션과 수업 중·수업 후 화면을 전환하고 학생을 선택해 답안 이력을 살펴볼 수 있다. 이 화면은 예시 또는 같은 출처(프로토콜·호스트·포트)의 같은 브라우저에 저장된 로컬 기록만 읽는다. 로컬 기록 선택 시 수업 ID를 비우면 예전의 ID 없는 기록을 볼 수 있다. 브라우저나 호스트가 바뀌면 로컬 기록은 공유되지 않는다.

## 기존 감자 미션

감자 미션의 `web/js/config.js`에 있던 기존 Apps Script 주소, `batch` 요청 형식과 `sciw_queue_v1` 재전송 큐를 그대로 사용한다. 현재 운영 서버를 호출하거나 시트를 읽고 쓰는 테스트는 하지 않았다. 서버가 바인딩된 시트를 사용하거나 `SPREADSHEET_ID` 속성을 사용하므로, 저장소에 시트 ID를 추측해서 넣거나 새 시트를 만들지 않았다. `apps-script/Code.gs`는 front-end의 기존 버전으로 복원했으며 서버 재배포는 하지 않았다.

기존 서버는 교사 신원 검증 없이 반 코드로 기록을 조회할 수 있는 구조다. 이 브랜치의 새 교사 화면은 서버 조회 기능을 추가하지 않으며 인증된 운영 화면이 아니다. 기존 접근 정책과 노출을 담당자가 검토하고, 실제 수업에서 교사 인증·수업별 접근 제한을 적용해야 한다. 학생 기록·기존 배포 설정을 바꾸지 않았다.

## 강철솜 미션

강철솜 `API_URL`은 비어 있어 같은 브라우저에만 기록한다. 현재 배포된 감자 서버가 m02를 지원하는지 확인되지 않았으므로 서버 URL을 복사해 넣는 것만으로는 전송하지 않는다. `M02_SERVER_VERIFIED`를 지정하지 않으면 서버 조회·쓰기 모두 보류하고, 미션 02 전용 재전송 큐에 기록을 남긴다. 임의로 값을 켜지 말고 먼저 **별도의 테스트 환경과 합성 데이터**로 배포 버전이 m02 저장 및 미션별 조회를 제대로 지원하는지 검증해야 한다. 지원이 없다면 기존 시트와 데이터 보존을 고려한 서버 업데이트를 별도 승인·검토 후 진행한다. 팀의 기존 배포를 수정하지 않았다.

미션 02의 새 큐는 미션 01과 분리된다. 이전 버전에서 공통 큐에 이미 남은 미전송 항목은 자동 이전하지 않는다. 이 경우 실제 전송 전 항목의 미션과 상태를 확인해 안전한 이전 방법을 결정해야 한다.

## 확인 방법

저장소 루트에서 `python3 -m http.server 8765` 후 `http://localhost:8765/`에 접속한다. Apps Script에 기록을 전송하지 않는 합성 테스트를 하려면 별도의 임시 복사본에서 감자 `API_URL`을 비운다. `node --test teacher/tests/*.cjs '감자 삼투/web/tests/'*.cjs '강철솜 질량 보존/web/tests/'*.cjs`는 합성 데이터와 모의 네트워크를 사용한다. 실제 Apps Script·스프레드시트 또는 브라우저 시각 검증을 대신하지 않는다.

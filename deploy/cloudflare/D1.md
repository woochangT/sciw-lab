# 학생 기록과 교사 진행 화면

학생 API는 `/api/student`에 기존 입장·복원·답안 전송을 보내고, 게임 판정은 `/api/student/judge`에 요청한다. 대시보드는 기존 조회 계약을 사용한다. Worker에서 저장과 AI 요청을 처리하며 운영 실행 경로는 Apps Script를 호출하지 않는다.

D1에서 `sessions`는 한 판의 상태, `session_events`는 답안과 대화 이력, `write_receipts`는 재전송 식별자를 보관한다. 같은 요청을 다시 받아도 D1이 한 트랜잭션에서 중복을 막는다. 이어 하기는 브라우저에 저장한 무작위 키로 조회한다. 번호만 아는 다른 브라우저에서 답안이나 초안을 열 수 없다. 교사 화면은 저장 후 WebSocket 변경 알림을 받고 같은 반만 다시 조회한다. 연결이 끊기면 기존 주기 조회로 돌아간다.

## 팀 개발

```sh
cd deploy/cloudflare
npm ci
npm run dev
node smoke-local.mjs http://localhost:8787
```

`npm run dev`는 로컬 스키마를 적용하고 테스트 판정·요약 응답을 사용한다. 브라우저에서 출력된 주소를 열고, `/teacher.html`에는 `teacher-local`로 입장한다. `smoke-local.mjs`는 양쪽 게임의 합성 테스트 행을 만든다. 교사 화면에서 **테스트 기록**을 켜면 볼 수 있다. 각 팀원은 자체 로컬 DB를 사용한다.

## 미리보기와 운영

브랜치 미리보기를 구성할 때 미리보기 전용 D1과 Worker 비밀을 연결한다. 운영 DB에는 승인된 배포만 연결한다. `wrangler.jsonc`의 예시 DB ID를 실제 환경별 D1 ID로 교체하고 마이그레이션을 적용한다. 운영 Worker 비밀에는 `TEACHER_PASSWORD`, 서명용 `TEACHER_PROXY_SECRET`, `OPENAI_API_KEY`를 설정한다. 감자의 선택적 AI 판정까지 켜려면 `ANTHROPIC_API_KEY`와 `M01_ANTHROPIC_MODEL`도 설정한다. 모델 이름과 호출 한도는 배포 환경에서 정한다.

전환 전 시트 스냅샷은 두 미션 탭의 헤더와 행을 포함하는 `{"records":{"m01":[...],"m02":[...]}}` JSON을 준비한다. `node deploy/cloudflare/import-from-sheets.mjs <snapshot.json> .local/import.sql`은 해당 파일로만 SQL을 생성한다. 로컬에서 `wrangler d1 execute DB --local --file <sql>`로 가져온 뒤 기존 미션별 세션·답안·판정 수를 대조한다. 운영 전환 때는 기존 기록의 최종 스냅샷을 받은 뒤 새 DB에 적용한다. 기존 시트의 세션은 교사 조회용으로 가져오며 브라우저 복원 키가 없던 과거 판은 학생 재입장으로 열리지 않는다.

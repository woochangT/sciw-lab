# 미션 02 AI 평가: 로컬 실험과 이전

## 로컬 수정과 운영 반영

로컬에서도 저장소의 실제 소스 파일을 수정한다. 로컬 전용 실험 서버가 그 소스를 `.local/llm-site`에 복사하고, 복사본의 기록 주소를 비우고 로컬 AI 평가 주소를 연결한다. 이 복사본을 GitHub에 올리는 것은 아니다. 실험이 끝나면 검토한 소스 변경을 커밋·push·PR·main 반영하는 순서로 옮긴다.

GitHub Pages의 화면 배포와 Apps Script 평가 서버 배포는 별개다. main에 올렸다고 Apps Script 코드나 배포 버전이 자동으로 바뀌지는 않는다. 실험 도구는 시트 수정이나 Apps Script 배포를 실행하지 않는다.

## 로컬에서 실행

Node 20 이상이 필요하다. 별도 패키지는 설치하지 않는다.

1. 저장소 루트의 `.local/openai-api-key` 파일에 사용자가 OpenAI 키만 직접 붙여넣고 저장한다. 이 파일은 Git에서 제외되고 웹으로 제공되지 않는다. 채팅이나 `config.js`에는 키를 넣지 않는다. 환경 변수 `OPENAI_API_KEY`도 지원하며 파일보다 우선한다.
2. 저장소 루트에서 `node tools/m02-local-server.cjs`를 실행한다.
3. 표시된 `http://127.0.0.1:8793/강철솜%20질량%20보존/web/` 주소를 연다. `localhost`가 아닌 표시된 주소를 사용한다.
4. 처음 생각·Q1·Q2·Q3·최종 변론을 제출하면 로컬 서버가 OpenAI를 호출한다. 기록은 해당 브라우저에만 저장한다. 실행 중 키 파일을 채워도 바로 적용된다.
5. 코드를 고친 뒤 서버를 종료하고 다시 실행하면 복사본이 갱신된다. 서버를 종료하면 로컬 API도 종료된다.

단계별 답만 빠르게 비교하려면 `http://127.0.0.1:8793/tools/m02-evaluator.html`을 연다. 현재 질문과 요소별 근거, 오개념, 형광펜 표시를 함께 볼 수 있다. 이 화면에서도 제출할 때만 유료 API를 호출하고 운영 시트에 기록하지 않는다.

모델 기본값은 `gpt-5.4-mini-2026-03-17`다. 처음 비교한 GPT-4.1 mini에서 단순 나열 답의 오통과와 요소 분류 오류가 관찰되어 바꿨다. GPT-5.4 mini의 추론 설정은 짧은 답 `low`, 최종 글 `medium`이다. `OPENAI_MODEL` 환경 변수로 모델을 바꿀 수 있다. 예시 확인은 실제 학생 답안 전체의 평가 성능을 검증했다는 뜻은 아니다. 포트는 `M02_PORT`로 바꿀 수 있다.

`/api/m02/status`는 키의 존재 여부, 모델, 루브릭 버전만 알려 주며 키 값을 반환하지 않는다. 키가 없거나 인증·요금·네트워크·응답 형식 문제가 생기면 평가를 중단한다. 답안은 입력란에 유지되고 오답 횟수와 힌트 단계는 올라가지 않는다. 규칙 판정으로 자동 전환하지 않는다.

게임은 AI 평가 한 가지 방식만 제공한다. 규칙 판정 코드와 모드 전환은 제거했다. 2026-11-02 별도 평가용 Apps Script를 배포하고 원본 `config.js`의 `JUDGE_API_URL`에 배포 주소를 연결했다. 기록용 `API_URL`은 기존 주소를 유지한다. 평가 서버에 장애가 생기면 입력을 보존하고 재시도한다.

로컬 실험 서버는 같은 게임 소스를 복사하고 평가 주소를 `/api/m02/judge`로 바꾼다. 평가와 결과 하이라이트는 같은 루브릭 v1.1을 사용한다. 배포된 게임은 클라우드 평가 서버를 사용한다. 로컬 OpenAI 키로 별도 실험하려면 위의 8793 서버를 사용한다. 배포 서버를 미리 확인할 때도 운영 기록 주소를 비운 복사본에서 진행한다.

## 루브릭 구현

기준 문서는 [강철솜 미션02 연결과 직접서술 평가루브릭](강철솜_미션02_연결과_직접서술_평가루브릭.md) v1.1이다. 같은 내용의 DOCX v1.1에는 2026-11-02 Q1 질문 변경과 피드백 운영 기준을 반영했다. 공통 구현은 `web/js/rubric02.js`이며 현재 버전은 `m02-docx-1.1.0`이다.

- 처음 생각: AI가 초기 생각과 오류를 진단한다. 관련된 생각이면 오답이어도 진행한다.
- Q1: “산소가 철에 붙었는데도, 마개를 막은 플라스크 전체 질량은 왜 그대로였나?”를 묻는다. 내부 결합·재배치와 경계를 넘는 물질 출입을 구분하여 전체 질량 불변을 설명했는지 읽는다. 철에 결합했다는 행방만으로는 충분하지 않다. 질문이 제공한 결합 사실이나 측정값을 반복하도록 요구하지 않는다.
- Q2: 질문 문맥에서 원래 공기에 있었다고 답하면 충분하다. 최종 W1b를 미리 요구하지 않는다.
- Q3: 질문 문맥에서 산소의 질량이라고 답하면 충분하다.
- 최종 글: 글 자체로 P1 또는 P2를 만족하고 핵심 오류 E1~E6가 없어야 통과한다. 앞 단계 답으로 빠진 설명을 채우지 않는다.
- 의미 판단과 요소별 met/partial/missing/uncertain 분류는 모델이 수행한다. 코드가 JSON 형식, 원문 인용, 필수 요소 조합을 확인하는 것은 키워드 채점이 아니다.
- API 출력에는 설명 시도, 연결 수준, 요소별 근거 인용, 오류, 보완 질문, 최대 3개 강조 구절이 있다. 통과 여부·분석·모델·버전을 로컬 시도 기록에 함께 남긴다.
- 게임 안의 보완 질문 `nextQuestion`은 교수의 “~해 보게”, “~아닌가?” 말투로 작성한다. 마지막 결과의 하이라이트 설명은 해요체로 작성하며, 부분 완료의 보완 안내는 판정 요소에 맞는 해요체 문구를 사용한다.
- 처음 생각의 재요청과 Q1~Q3의 재질문은 단계별 문구를 사용한다. Q1에서는 플라스크 전체 질량 불변의 설명을 보완하도록 되묻는다. 화면의 첫 질문과 API의 질문은 같은 단계 정의를 사용하며, 판정 기록에는 화면에 보였던 대사와 기준 질문, 후속 질문도 남긴다.
- 보완 피드백에는 원래 질문과 후속 질문을 함께 보여 준다. Q1에서는 “안에서만 옮겨 붙었을 뿐이어서 전체 물질의 양은 같다”처럼 내부 재배치와 전체 질량 불변을 잇는 설명을 인정한다. “아무것도 이동하지 않았다”와 “플라스크 밖으로 물질이 드나들지 않았다”를 구분한다. API 대기 중에는 교수 말풍선과 제출 버튼에 “흠…”을 표시한다.
- 강조 구절은 실제 원문의 위치를 확인하여 표시한다. 겹치는 범위는 중복해서 칠하지 않는다. 모델이 준 HTML을 삽입하지 않는다. 처음 생각과 의미를 비교해 새 연결인지 구분한다.
- 카드 출처는 삽입 당시의 글자 이력으로 추적한다. 편집 뒤 남은 카드 글자도 구분하며 카드 표현을 독립 작성이라고 칭찬하지 않는다. 카드 도움 여부가 과학 내용의 통과 기준을 바꾸지는 않는다.

## 실험 결과를 볼 때

사람이 먼저 판정한 짧은 정답, 부분 답, 오개념, 모호한 답, 단어 나열과 채점 명령 사례를 준비해 AI와 비교한다. 틀린 답의 통과와 맞는 답의 불통과를 따로 기록한다. 문서의 경계 예시와 실제 학생 답안을 모두 확인한 뒤 프롬프트·모델을 결정한다. 코드 연결을 완료한 것과 AI 판정 성능을 확인한 것은 별개다.

특히 Q2의 “공기 중에 있었다”, Q3의 “산소의 질량이다”, Q1의 보존 법칙 이름만 있는 답, 숫자·법칙을 나열한 최종 글, 명시적인 자기 수정, 과학 오류와 정답이 공존하는 답을 비교한다. 하이라이트는 실제 구절·W 유형·칭찬의 정확성·처음 대비 성장·카드 출처를 함께 확인한다.

## Apps Script 평가 서버

`node tools/export-m02-apps-script.cjs`는 같은 루브릭과 평가 전용 진입점을 `.local/m02-apps-script`의 `Code.gs`, `Rubric.gs`, `appsscript.json`으로 생성한다. 로컬 파일만 만들며 업로드하지 않는다.

별도 평가 전용 프로젝트에 이 세 파일을 적용한다. 사용자가 Script Properties의 `OPENAI-API-KEY`, `M02_JUDGE_ENABLED=true`, 필요하면 `M02_OPENAI_MODEL`을 설정하고 테스트 배포를 만든다. 브라우저의 `JUDGE_API_URL`은 그 배포 URL만 가리키고 기록용 `API_URL`은 별도로 둔다. 기존 운영 프로젝트의 `Code.gs`를 이 파일로 덮어쓰면 안 된다. 기존 프로젝트와 합칠 경우 먼저 실제 운영 코드를 대조하고 승인된 범위의 변경만 반영한다.

평가 서버는 전체 하루 300회·분당 30회의 호출 상한을 기본으로 적용한다. `M02_DAILY_LIMIT`과 `M02_MINUTE_LIMIT` 서버 속성으로 조정할 수 있다. 상한은 호출자 인증을 대신하지 않으며 공개 주소를 아는 사람은 요청할 수 있다. 평가 서버는 시트에 접근하지 않고 외부 API 호출 권한만 사용한다. 자세한 설정은 [AI 평가 서버 안내](../apps-script/m02-evaluator/README.md)를 따른다.

## 2026-11-01 로컬 확인 결과

- GPT-5.4 mini에서 기준 예시 12건의 진행 판정, 과학 오류 분류, 최종 설명 경로가 예상과 일치했다. 처음 생각의 열 오개념은 진단 후 진행, 짧은 Q2·Q3 정답은 통과, 법칙 이름만 적은 Q1과 단순 나열 최종 글은 보완 대상으로 구분했다.
- 기준 예시와 별도로 만든 새 예시 8건도 확인했다. 이 중 복합 오류 최종 글 1건은 처음에 응답 길이 한도로 미완료 처리되었다. 최종 글 응답 예산을 늘린 후 해당 건을 다시 실행하여 E4와 보완 판정을 확인했다. 나머지 7건도 예상과 일치했다.
- 응답 계약 검사에서 두 설명 경로, 핵심 오류의 통과 차단, 모호함, 없는 원문 인용 거부, 표시 위치, 중복 역할 제거, 카드·직접 입력 출처를 확인했다.
- 로컬 복사본의 실제 게임 입력·제출 함수를 사용해 호출 실패 시 답안 보존과 제출 횟수·힌트 단계 유지, 재시도를 확인했다. 실험 전체를 처음부터 끝까지 연속 플레이한 검증은 별도로 남아 있다.

이 수치는 소수의 합성 예시에 대한 확인이다. 실제 학생 답안을 대상으로 한 정확도, 오통과율·오탈락률, 반복 호출 안정성을 확정한 결과가 아니다. 예시를 보며 조정한 부분도 있으므로 운영 전 별도 답안 묶음으로 검토한다. 로컬 원자료는 `.local/m02-calibration-results.json`, `.local/m02-heldout-results.json`, `.local/m02-heldout-retry.json`에 있으며 Git에 포함하지 않는다.

- 버전 3의 합성 답안 9건은 예상한 진행 판정과 일치했다. 추가한 P1 예시는 W1a 충족·경로 1 통과, 외부 유입 사실만 적어 P1·P2를 완성하지 못한 예시는 W1a 미충족·보완 판정이었다. 요청 시간은 약 2.8~15.7초였다.
- 초기 연결 점검 원자료는 `.local/m02-cloud-evaluation.json`, 최신 재확인 원자료는 `.local/m02-cloud-v3-results.json`에 있으며 Git에서 제외한다.
- 이 확인은 합성 예시에 대한 연결 점검이며 실제 학생 답안 전체의 평가 정확도를 검증한 결과는 아니다. 운영 기록 서버나 팀 시트에는 확인용 답안을 보내지 않았다.
